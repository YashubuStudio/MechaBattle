# UI全面見直し 現状調査・ギャップ分析（Claude、2026-10-16）

ユーザー依頼: 「戦闘UIおよびシステム自体のUI周りを全面的に見直し、ゲーム全般およびこのゲームに必要な物を一通りそろえ、見やすくしてください。」

`Assets/Game/Runtime/Playable/PlayableUI.cs`を全読し、現在存在する画面・要素を一覧化した上で、(a)一般的なマルチプレイヤー対戦ゲームで標準的に必要とされる要素、(b)このゲーム特有の要件（AGENTS.md/SYSTEM_DESIGN）、の両方と比較しました。

**前提の制約**: Claudeは画面を実際に見る手段がありません（Unity Editorでの視覚確認は不可）。したがって「見やすくする」（文字サイズ・配置・配色・レイアウト調整）は盲目的に実装すると悪化させるリスクがあります。本調査では**機能として明確に欠けているもの**（見た目に関わらず存在しない機能）を優先的に洗い出し、それらを提案します。レイアウト・配色等の純粋な視覚調整は、Unity Editorでの実際の見た目確認ができる方（ユーザー/GPT）との反復作業が必要と明記します。

## ギャップ分析

### 明確に欠けている機能（見た目に関わらず存在しない）

1. **スコアボード/戦績一覧が存在しない**: 50vs50という規模にもかかわらず、試合中に「誰が/どのチームがどれだけ活躍しているか」を見る手段がゲージ以外にありません。確認したところ、`SimulationCounters`（`UnitsDestroyed`等）は**全軍合計のみ**で、個人/チーム別の撃破数・被撃破数・ダメージ量は一切集計されていません（Results画面の`ResultStats`も「全軍の撃破数」のみ）。スコアボードを作るには、Simulation側に新規のper-slot集計（誰が誰を倒したか）を追加する必要があり、想定より規模の大きい追加実装になります。
2. **設定画面（グラフィック/音声/感度調整/キー再割当）が存在しない**: `config`には`mouseSensitivity`等の値がありますが、ゲーム内でこれを変更するUIがありません。ロック方式の切替（`LockModeSetting`）のみ3画面に分散して存在しますが、それ以外の設定項目（感度、音量、グラフィック品質等）を調整する専用の設定画面自体がありません。
3. **キルフィード/戦闘ログが存在しない**: 誰が誰を倒したか、拠点がいつ占領されたか等のイベント通知がありません（`IncomingLockWarning`は自分がロックされた時のみ）。
4. **被弾方向インジケータが存在しない**: `UpdateDamageFeedback`は画面全体を赤くフラッシュするのみで、どの方向から撃たれたかが分かりません。50人規模の乱戦では死角からの被弾が多いと想定され、方向表示は有用と考えられます。
5. **マッチイベント通知が薄い**: 本拠点が攻撃されている、味方が撃破された等の通知がありません（`TryGetCombatEvent`の`CoreHit`等、Simulation側のデータは既に存在するため、UIへの反映は追加実装で対応可能）。

### このゲーム特有の要素（存在確認済み、おおむね揃っている）

DP/よろけ/転倒、ブースト/オーバーヒート、黄/赤ロック状態、拠点占領状況、チームゲージ、味方ロック時のHP表示（前回セッションのSUPPORT-12）は全て存在を確認しました。汎用機/専用機の表示は`PlayableEntry.cs`側の動的生成のため本調査では未確認です。

### 見た目・配置に関する所見（視覚確認なしでの限定的な指摘）

- HUD要素の密度が高く（武器情報・デッキ状況・ロック状態・戦闘状態など複数のテキストブロックが右側に集中）、実際の画面でどう見えるかはUnity上での確認が必須です。
- 文字サイズは14〜62の範囲で用途に応じて変えられており、設計自体は意図的に見えます（タイトル46〜62、本文19〜25、注記14）。これが「見やすい」かどうかは実機確認が必要です。

## 提案（優先順位付き）

1. **【実装可能・確度高】マッチイベント通知の追加**: 既存の`TryGetCombatEvent`（CoreHit等）をHUDの通知領域（例: 画面上部にトースト表示）へ接続。データは既にSimulation側にあるため追加実装のリスクは低いと判断します。
2. **【規模大】簡易スコアボード**: `SimulationCounters`は全軍合計のみのため、Simulation側にper-slotの撃破/被撃破集計を新規追加する必要があります（`RegisterLockedHit`/`RecordImpact`等の既存の命中記録経路に攻撃者/被害者のスロットが載っているため、集計先を追加する形は可能と考えられますが、Game.Simulationのコア構造への追加のため影響範囲の見極めが必要です）。
3. **【実装可能・確度中】被弾方向インジケータ**: 被弾時の攻撃者方向を画面上に矢印等で表示。`RecordImpact`等のダメージ記録に攻撃者位置が含まれているため、データ自体は取得可能と考えられます。
4. **【規模大・要検討】設定画面**: 感度/音量/グラフィック品質の調整UI。既存の`mouseSensitivity`等の値をUIから変更し、`PlayableConfiguration`/プレイヤープロファイルへ永続化する仕組みが必要（`LockSettings`の永続化パターンが参考になります）。
5. **【視覚確認必須】レイアウト・配色・文字サイズの調整**: Unity Editorでの実際の見た目を確認しながらの反復作業が必要です。Claudeは現時点でこれを単独で安全に進める手段がありません。
