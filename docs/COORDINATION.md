ユーザーは適宜の相互監視と協力を明示している。制作は担当を分けて続ける。

1. 作業開始・統合前・テスト後にWORK_BOARD.mdと相手の差分を確認する。
2. GPTはドメイン/ルール/テストを担当し、ClaudeのAdapter/Generatorが型・所有権・知覚制約を守るかレビューする。
3. ClaudeにはGPTのCT/弾薬/ゲージ/本拠点/入力検証/テスト抜けをレビューしてもらう。
4. 指摘はdocs/reviews/に別ファイルで残す。レビュー依頼・受領・修正・再試験を区別する。
5. 本体の同一ファイルを同時に直さない。P0_SIMULATION_API.mdを共有契約とし、変更を通知する。
6. 無反応でも相手がレビュー済みと推測しない。担当内の独立作業を進め、受領待ちを記録する。

1. WORK_BOARD冒頭の最新担当と実差分を確認し、引き取る範囲・要件・依存・完了条件を記録して着手する。解除済み/未担当の範囲は承認待ち不要。

## 毎区切りの予約解除と記録（RELEASE-14）

GPT / Claude共通。小変更や検証が一段落した時点で必ず予約を解除する。レビュー/ユーザー/実機確認待ち、別タスクへの切替、ターン終了・中断前も同様。リソース不足になるまで保持しない。タスクが未完了でも、実際の書込みを完了させた範囲を解除して引継ぎ可能にする。相手の承認・受領は解除条件にしない。タスクownerの履歴と編集予約を分ける。

各区切りで次の形式をWORK_BOARDへ残す。再開時は最新記録/実差分/実行状態を読み、必要な最小範囲だけ再取得する。

~~~text
task: <要件/タスクID>
owner: <GPT または Claude>
status: <完了 / 未完了 / レビュー待ち等>
lock: released
released_paths: <解除した全パス>
saved_changes: <実際に保存した変更>
validation: <実行者・結果・ログ、未実施は未実施>
remaining: <未完了・未解決>
next_action: <次の具体的1手>
running_processes: <なし / コマンド・セッションID・状態・書込み先>
~~~

書込み中の処理があるパスを解除済みと偽らず、自分の処理の完了を確認して解除する。やむを得ない停止は実状態を記録し、再開者が確認する。相手のプロセスやGit/Unity/OSのロックファイルを無断で終了・削除しない。解除のためにユーザーへ再確認を要求しない。
