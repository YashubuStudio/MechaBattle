# 操作感・バランス全体レビュー（Claude→GPT、2026-10-16）

ユーザー依頼（原文）:
> 全体的なコストや火力、回復量、マップ等のバランスを見直し、調整を行ってください。操作周りも、ジャンプ中のバズーカを当てる難易度が高すぎたり、視点が高く格闘の当たり判定が狭すぎる気がします。D格中の状態にも当たり判定を追加するなどして、全体的にいい感じにしてください。

Simulation/Playable（GPT領域）に深く関わるため、Claudeは直接編集せず調査結果と提案をまとめます。操作感3点は具体的な原因を特定できたものから優先度順に記載し、バランス全体は実際の数値を計算した結果を正直に報告します（根拠のない数値変更はしていません）。

## 1. D格（Dash格闘）が当たらない問題 【訂正: 前提が誤っていました、再調査中】

**訂正（2026-10-16、task #34実装中に発覚）**: 以下の「原因を特定しました」は`p0Simulation`ブロックを見て書いたものでしたが、実際にPlayableが使うのは`playablePrototype`ブロック（`PlayableConfiguration.Apply()`経由）です。`playablePrototype.seamlessMeleeEnabled`は実際には**true**でした。つまりD格のダッシュは瞬間移動ではなく、`AdvanceMeleeLunge`による漸進移動（windup終了時にちょうど到達するよう毎tick距離を再計算）で実装されています。下記の「原因」はこの前提の誤りにより成立しません。詳細はWORK_BOARD.mdの訂正エントリを参照してください。再調査の仮説（未確証）: ダッシュの方向は入力開始時に一度だけ固定され、windup中の対象の移動を追跡しないため、対象がわずかに動くだけで最終ヒット判定から外れる可能性があります。

**（誤り・参考として残します）原因を特定しました**: `config.seamlessMeleeEnabled`は現在のプロトタイプ設定では**未設定（false）**です。このため`StartMelee()`内の格闘ダッシュは`MoveHorizontal(u, ...)`による**瞬間移動**（windup開始時に`lungeMeters*power`分を一瞬で位置へ加算、Dashは5m）で実装されています。

一方`Melee()`の命中判定は、windup終了後の**1ティックだけ**、その時点の`u.X,u.Z`（＝瞬間移動後の最終位置）から対象への距離・角度を見ています。つまり:
- ダッシュの軌道上に敵がいても、**最終到達点からの判定しかしていない**ため、ダッシュが敵を飛び越えてしまう（オーバーシュート）、または届かない（アンダーシュート）場合、"見た目は突っ込んでいるのに当たらない"という現象が起きます。
- これはユーザーの「D格中の状態にも当たり判定を追加して」という要望と正確に一致する実装上のギャップです。

**提案**: `StartMelee()`で瞬間移動を行う**前**の位置を`u.MeleeOriginX, u.MeleeOriginZ`として保存し、`Melee()`の対象選定ループで、`a.lungeMeters>0`のスタイル（Dash/DashCombo、将来追加のチャージ格闘も該当）については、単純な点対点距離ではなく**原点→終点の線分と対象の最短距離**（スイープ判定）で命中可否を判定するよう変更する。これにより軌道上にいた敵も正しく巻き込めます。
- `config.seamlessMeleeEnabled`を有効化する方法もありますが、それだけでは`Melee()`の判定が1ティックのみである点は変わらないため、**判定ロジック自体の修正が本質的な解決**と考えます。有効化するかはGPTの判断にお任せします。

## 2. 格闘の当たり判定が狭い・視点が高い 【中確度】

**現状確認**: `Melee()`の命中ループは水平面のヨー角コーン（`halfAngleDegrees`: 通常60°/コンボ65°/D格50°/Dコンボ55°）のみを見ており、カメラのピッチ（上下視点）は一切関与しません。ただし**高さ差のゲート**`Math.Abs(t.Y-u.Y) > a.range*0.75f`が存在し、range×0.75（通常2.55m、D格2.85m、Dコンボ2.625m）を超える高低差では無条件に外れます。

FIELD-04で追加された地形（段差3.6m/5.4m、塔・壁8m）と組み合わせると、段差の上下にいる相手への格闘はこの高さゲートで簡単に外れます。カメラ(`cameraHeight=2m`/`cameraHeadHeight=2.2m`)が機体の全高(`unitHeight=2.47m`)に近い高さにあるため、見た目の視点が高くこの高さズレを視認しにくく、「判定が狭い」という体感につながっていると考えます。

**提案**:
- 高さゲートを`a.range*0.75f`から**固定の許容値**（例: `meleeVerticalToleranceMeters=4.0`、3.6mの段差を確実に超える値）へ変更。range依存をやめることで、段差のある地形でも格闘が機能しやすくなります。
- 補助的に`halfAngleDegrees`を全スタイルで**+10°程度**広げる（通常60→70、コンボ65→75、D格50→60、Dコンボ55→65）。
- カメラ`cameraHeight`/`cameraHeadHeight`をやや下げる（例: 2→1.6、2.2→1.9）提案。ただしサードパーソンのショルダーカメラのブーム距離/オフセットがこの2値だけで決まらない可能性があり（`PlayableEntry.cs`のコメントにある"shoulder camera"のオフセット実装箇所はClaudeが未特定）、実際の見た目の調整はGPTの確認をお願いします。

## 3. ジャンプ中のバズーカが当てづらい 【低〜中確度、要実機確認】

**現状確認**: `weapon.bazooka`は`projectileSpeed=50`の非誘導弾で、`redLockRange=45`以内なら`TryRedTarget`による誘導（Homing）が効きます。45mを超えると誘導なしの直線弾になり、ジャンプで上下に動く相手を外部リード（予測）なしで当てる必要があります。BOT側には`botProjectileLeadFraction`という予測リード機能がありますが、プレイヤー入力側に同等の補助はありません。

これは「非誘導弾で空中の相手に当てる」という**本来スキルが要求される場面**である可能性が高く、必ずしもバグではないと考えます。ただ、現状の値だと厳しすぎるという体感であれば、以下のいずれか（複合可）を提案します:
- `redLockRange`を45→60m程度に拡大し、誘導が効く範囲を広げる（手軽で副作用が少ない）。
- `blastRadius`を5→6.5m程度に拡大し、わずかな外しでも爆風で当たるようにする（火力自体は変えない）。
- プレイヤー入力側にも軽い垂直リード補正を追加する（最も効果的だが実装範囲が大きい、Playable側の入力/エイム処理に関わる）。

実機確認（本当にバグなのか、意図通りの高難度なのか）をGPTにお願いしたいです。

## 4. コスト・火力・回復のバランス分析

実際の数値（`config/prototype-defaults.json`）を使い、弾倉切れ・リロードまで含めた**継続DPS**を計算しました（単純な`damage/intervalSeconds`では弾倉の小さい武器が過大に見えるため、`magazineCapacity`・`reloadSeconds`を含めた1サイクルの平均値で算出）。

| 武器 | ダメージ/発 | 継続DPS(概算) |
|---|---|---|
| carbine | 36 | 115.5 |
| longrifle | 138 | 162.4 |
| cannon | 400 | 125.0 |
| bazooka | 500 | 135.1 |
| charge | 880 | ~357（**上限値、フルチャージ時間が未反映のため実際はこれより低い**） |
| beam | 38 | ~138（**上限値、継続ビームの仕様が単純な弾倉モデルと合わないため要GPT確認**） |
| melee(通常) | 760 | 2451（近接のため接近リスクを負う前提の値、単純比較は不適切） |

**結論**: carbine/longrifle/cannon/bazooka の4種は継続DPSが115〜162の範囲に収まっており、**既に比較的よく揃っている**ことが分かりました。想定していたような明確な過剰火力・過小火力は見つかりませんでした。charge/beamは発射モード特有の仕組み（チャージ時間・ビーム持続時間）を単純な弾倉モデルに当てはめきれておらず、上記の値は上限の見積りです。実際の値はGPT側で発射モードの実装を踏まえて確認いただくのが確実と考えます。

**回復量**: 本拠点補給(`homeHealthPerSecond=30`/`homeShieldPerSecond=40`)は上記継続DPS(115〜162)より明確に低く、集中攻撃を受けている状態を逆転させる力はない設計（意図通りと判断）。修理ポッド(`podShieldPerSecond=160`)は装備枠を使う投資に見合う強さ、修理ガン(継続ヒール概算約208/秒)は専用武器枠として最も高い回復力、という序列になっており、投資量に応じた強さの階層は妥当に見えます。

**結論として、現時点の静的な数値分析からは経済バランスの明確な欠陥は見つかりませんでした。** 根拠のない数値変更は避け、実際のプレイフィール（「強すぎる/弱すぎる」という具体的な武器名や場面）が分かれば、それに絞った調整を次に提案します。もし「全体的に火力を上げて試合を速くしたい/遅くしたい」等の方向性があれば、その方向をお知らせいただければ具体的な倍率を提案します。
