# Project: 100-Slot Mecha Battlefield Simulator

**ステータス:** 企画・設計ベースライン v0.2 / 2026-10-15  
**実装対象:** Windows x64、Unity 6.3 LTS / C#、オフラインから着手  
**開発形態:** 人間が企画・品質判断、AIエージェントが実装・自動テストを担当

> ガンダムオンラインの大規模戦闘構造から着想を得た、**オリジナルの**50対50＋両軍指揮官ロボット戦闘ゲーム。商用素材や既存IPの名称・デザインの流用はしない。

## 絶対に維持する原則
- 各軍50機体スロット＋指揮官1枠。空き操作枠はBOTで補う。初期オフラインは人間1名・BOT99名・指揮官AI2名。
- **最大100機が同時に戦闘可能**。CT待ち・撃破・再出撃によって、実際の生存機数は100未満にもなる。
- プレイヤーは指揮官の命令に従う義務を負わない。命令不履行ペナルティは禁止。
- **本拠点は各軍最低2ヶ所。標準試験マップは各軍3ヶ所。** 1ヶ所だけのマップは禁止。複数拠点による防衛分散・裏取りの成立を重視する。
- 敵本拠点への攻撃が、戦力ゲージを減らす最も効率的な主要手段。MS撃破でもゲージが減少。
- 中継拠点は人数差によって奪い合い、前線リスポーン・制圧の足場になる。
- 複数本拠点は防衛しやすい一方、分散により生じる防衛の穴は単独のネズミ・凸・核で突ける。
- AI側には全知情報を与えず、索敵・戦況観測に基づいて意思決定させる。
- 一般兵BOT・4機小隊BOT・両軍指揮官AI。全BOTに機体デッキ/CTと補給ルールを適用。
- **自動カウンター（格闘自動反撃・自動防御割込み等）は実装しない**。
- 赤ロックは存在する。BOT→人間プレイヤー方向のみ赤ロック距離を短縮する（対人関係は別途調整可能）。
- 開発PCはWindows。Android/Web/macOS/UWP向けビルドは初期スコープ外。
- 2019年前後の中級ゲーミングPCで、オフライン最大100機・1080p/60fpsを達成目標とする（未検証）。

## 企画と実装の進行
P0 ベンチマーク/試合モデル → P1 戦闘・デッキ・CT → P2 拠点・補給・BOT自動試合 → P3 小隊AI → P4 指揮官AI → P5 演出と調整 → P6 将来のオンライン。

## 開発AIへの最初のタスク
`AGENTS.md`と全ドキュメントを読み、機能一覧と依存関係図を確認する。まずはP0として、シーンをEditorスクリプトで生成し、**50対50スロット、各軍3本拠点、100機の軽量移動・射撃・撃破・再出撃・中継拠点占領をテストする最小シミュレーション**を作成。ビルド/PlayModeテスト/性能レポートを出力する。詳細なロボットモデルや演出は実装しない。
