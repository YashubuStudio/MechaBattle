# AGENTS.md — Mecha Battlefield 開発AI共通ルール

**あなたの役割:** AIエージェントとして、ゲームを安全に段階実装し、コンパイル・試験・測定・変更記録まで実施する。人間はディレクションと試遊判断を担当する。

## 1. 作業開始前
1. `README.md`, `GAME_VISION.md`, `GAME_SPEC.md`, `SYSTEM_DESIGN.md`を読む。
2. 要件IDと現在の実装の対応を確認し、変更対象・依存先・テストを列挙。
3. `git status`を確認。既存変更を消さない。大きな変更の前にブランチ/コミット単位で保護。
4. `[TBD]`を勝手に製品仕様として固定しない。開発に必要なら`prototype-defaults.json`へ仮値と理由を記録。

## 2. 絶対禁止
- 50対50の枠を減らすことでベンチマークを「達成」したことにする。
- **各軍2ヶ所未満の本拠点を持つマップを生成・採用する。** 初期の標準試験マップは各軍3ヶ所（仮設定）で作る。
- 試合の主目的を本拠点攻撃から撃破数競争に変更する。
- 指揮官が人間プレイヤーを操作・強制移動・命令違反処罰する機能。
- 敵の全位置をAIへ無条件に公開する。
- BOTのCT/弾薬/補給を無視する。BOT用の隠し無敵補正を作る。
- 格闘時の**自動カウンター**、自動反撃、無入力割込み。
- 赤ロックのBOT→人間短縮ルールを削除する。
- 無断でAndroid/Web/macOS/UWPビルドモジュールを導入する。
- 自動テストを削除・無効化して合格扱いにする。
- 既存IPの機体、ロゴ、音声、マップのコピーを入れる。

## 3. ソフトウェア構造
- Unity依存のない純粋な状態管理・ルールを優先。AdapterでUnity物理/描画/入力を接続。
- `UnitCommand`の共通形式でプレイヤー/BOT/将来の通信入力を扱う。
- 真の戦況と各軍が知る情報を分け、AIは知覚情報だけで判断。
- 更新負荷・GC割当を意識するが、測定せずにフルECS化しない。
- GameObject・Prefab・Sceneの直接YAML編集を避け、Editorの生成コードを使う。

## 4. 実装サイクル
設計要約 → 小さい変更セット → ユニットテスト → PlayModeテスト → Windowsビルド → 必要時ベンチマーク → 変更ログ/既知問題の更新。操作可能な環境がない場合、**未実施を明示**し、成功したと偽らない。

## 5. 完了報告の形式
- 対応要件IDと変更したファイル
- 追加/変更した機能と仮設定値
- 実行したテストおよび結果（未実施は未実施と記す）
- FPS/GC/CPU/GPUの計測条件と値（性能に影響する変更の場合）
- 後続タスクと未解決リスク

## 6. 初回タスク
P0技術検証から開始。最初からアート、武器大量追加、指揮官チャット演出、オンライン同期には進まない。まず100機・各軍50枠・各軍3本拠点の自動対戦基盤とテスト実行を確立し、各軍2ヶ所未満の本拠点定義を拒否するバリデーションを実装する。
